# 激励轨迹选取与 Fourier 参数设计分析

面向对象：`ARX5 2023 + D435i` 当前项目模型，以及一般串联机械臂的动力学参数辨识。

分析时间：`2026-04-28`

---

## 1. 结论摘要

### 1.1 核心结论

1. **激励轨迹不是“与机器人无关”的通用模板。**  
   机械臂的可辨识参数集合首先由构型、关节轴排列、质量分布、传动/摩擦模型、是否带 payload 决定；激励轨迹只是为这个特定模型提供足够的信息量。

2. **有限 Fourier / 改进 Fourier 仍是串联机械臂动力学辨识的主流工程形式。**  
   原因不是“它天然最优”，而是它便于在关节位置、速度、加速度边界内做参数化优化，并且容易处理周期性与零边界条件。

3. **对当前 `ARX5 2023 + D435i` 项目，现有默认 Fourier 轨迹更像“安全的小角度通用激励”，不是“针对 payload-rich 基参数的强激励”。**  
   主要原因有三条：  
   - 当前轨迹以 `q0=0` 为基线，执行前还会先 `reset_home()`；  
   - `joint2` / `joint3` 在 URDF 中是 `[0, π]`，而当前实测数据显示这两个关节的负半周基本没有被真正执行；  
   - 当前 `--optimize` 用的是代理特征矩阵，不是真实动力学回归矩阵。

4. **对本项目最关键的不是先增加谐波数，而是先把激励中心姿态移到更合适的“抬臂区间”。**  
   若仍围绕绝对零位做对称小角度 Fourier，`joint2` / `joint3` 很容易落在限位/跟踪死区附近，导致“计划上看有激励，实机上没有真正扫到”。

5. **如果当前目标是把“带 D435i 的整机”作为辨识对象，优先激励 `joint2` / `joint3` / `joint4`。**  
   因为项目已把相机等效载荷合并到 `link6`，重力杠杆臂主要通过肩、肘、腕俯仰这几级传到基座侧。

### 1.2 对当前命令的直接判断

你现在这条命令：

```bash
uv run arx5ctl ident-run \
  --adapter sdk \
  --model X5 \
  --interface can0 \
  --profile fourier_multisine \
  --duration 12 \
  --harmonics 5 \
  --optimize \
  --candidate-count 12 \
  --sample-hz 100 \
  --output runs/ident-sdk-fourier \
  --execute \
  --confirm "I UNDERSTAND THIS WILL MOVE THE ARM" \
  --json
```

**对“安全试跑”是正常的，对“强辨识激励”并不理想。**

- 从代码看，默认幅值上限被卡在 `0.12 rad`。
- 从实测看，`joint2` / `joint3` 明显没按计划幅值真正扫开。
- 从论文标准看，当前优化目标也不等于“让真实回归矩阵最可辨识”。

因此，“机械臂没有完全抬起来、活动范围只是回中附近一点点”，**对当前实现是可解释的，不是异常；但它说明这条轨迹不适合作为 payload-rich 主辨识轨迹。**

## 2. 论文结论：激励轨迹选取到底受什么约束

下面先只讲论文共识，再落到本项目。

### 2.1 证据

#### 证据 A：可辨识参数集合先由机构本身决定

`Briot & Gautier, 2021` 的综述指出，刚体动力学模型中并非所有惯性参数都能独立辨识；由于几何与关节结构的内在性质，存在**无论做什么实验都无法分开的参数组合**，因此必须先讨论 **base parameters**，再谈激励轨迹。  

这意味着：

- 构型不同，最佳激励就不同；
- 关节轴平行、对称、共线、某些 link 很轻或运动范围受限时，信息矩阵会退化；
- “同一条 Fourier 参数”不可能对所有机械臂都同样好。

#### 证据 B：最优激励轨迹通常要直接针对回归矩阵或参数协方差来设计

`Swevers et al.` 的机器人辨识教程把周期轨迹最优设计写得很明确：  

- 用参数化轨迹（常见就是有限 Fourier）来覆盖整个实验；
- 在满足关节约束的前提下，优化动力学回归矩阵的条件数、最小奇异值、或参数估计协方差；
- 目标不是“运动看起来丰富”，而是“让基参数估计数值上稳定、方差小”。

这也是为什么论文中常见指标包括：

- `cond(Y)` 或 `cond(W)`；
- Fisher information；
- 参数协方差矩阵的 `D-optimality / A-optimality / E-optimality`；
- 对估计方差、偏置、噪声敏感性的综合目标。

#### 证据 C：有限 Fourier / 改进 Fourier 受欢迎，是因为它易于带约束优化

`Swevers` 的教程把“有限 Fourier 级数”作为典型轨迹参数化方式。  
`Huang et al., 2012` 进一步强调“modified Fourier series”的工程优点：能保持周期激励的频域表达，同时通过额外约束/边界处理，让起止点更平滑，减少大冲击和跟踪误差。

这和本项目当前做法一致：

- 核心信号是有限 Fourier 多正弦；
- 起止边界再乘一个五次零边界包络；
- 目的正是让起止位置、速度、加速度回到零。

#### 证据 D：真实机器人上的激励设计必须显式考虑边界、安全、碰撞与未建模动态

经典文献和近年的 tool-equipped robot 工作都强调，理论最优轨迹必须服从：

- 关节位置、速度、加速度边界；
- 电机/驱动器电流或力矩边界；
- 跟踪器可实现的频带；
- 结构柔性、齿隙、未建模共振；
- 工具/传感器带来的附加碰撞约束。

`2024` 年针对带工具协作机械臂的校准工作甚至显式用 **virtual holonomic constraints** 约束轨迹，以避免危险构型和自碰撞。

### 2.2 对一般机械臂的推论

#### 推论 1：先选“模型目标”，再选轨迹

如果目标不同，轨迹也应不同：

- **只识别重力/载荷项**：优先准静态或低频单关节/少关节扫描；
- **识别摩擦**：优先正反向、多个恒速区间；
- **识别完整刚体基参数**：优先多关节耦合周期轨迹；
- **同时带显著柔性/驱动器效应**：激励不能盲目加高频，否则会把刚体模型打坏。

#### 推论 2：构型越“接近退化”，越要避开坏姿态

常见坏情况：

- 两个关键关节始终只在很窄角度范围内抖动；
- 重力杠杆臂几乎不变；
- 某些关节一直靠近限位；
- 末端 payload 对基座侧关节的力矩变化不明显；
- 实机实际轨迹与规划轨迹偏差很大，导致你优化的是“命令轨迹”，但辨识用的是“执行后的实测轨迹”。

#### 推论 3：先解决“可执行性”，再增加谐波

如果低阶 Fourier 都跟踪不好，提高谐波数通常只会更糟。  
高谐波会更快推高：

- 峰值速度，约随 `A * H / T` 增大；
- 峰值加速度，约随 `A * H² / T²` 增大；

其中：

- `A` 是幅值量级；
- `H` 是最高谐波数；
- `T` 是周期。

因此工程顺序通常是：

1. 先选合适中心姿态；
2. 再放大主关节幅值；
3. 再决定是否增加谐波数；
4. 最后才追求更激进的条件数优化。

## 3. 本项目的直接证据

### 3.1 当前轨迹实现到底做了什么

#### 证据

- `src/armctrl/identification/trajectories.py:55`  
  当前 Fourier 轨迹使用五次零边界包络 `_zero_boundary_envelope()`。
- `src/armctrl/identification/trajectories.py:221`  
  `generate_fourier_multisine()` 以有限 Fourier 级数为主体，默认 `duration=12s`、`harmonics=5`、`amplitude=0.12 rad`。
- `src/armctrl/cli/arx5ctl.py:433`  
  `ident-run --profile fourier_multisine` 默认走这套生成逻辑。
- `src/armctrl/cli/arx5ctl.py:438`  
  默认幅值逻辑是 `min(0.12, 0.02 * duration^2)`，在任何实际会用到的 `duration` 下几乎都会饱和到 `0.12 rad`。

#### 推论

对当前 CLI 来说，**如果你不显式传 `--amplitude`，延长 `--duration` 不会自动带来更大姿态摆幅**。  
它只会降低频率和导数量级，不会让机械臂“抬得更开”。

### 3.2 当前执行链路默认围绕 `q0=0`

#### 证据

- `src/armctrl/identification/README.md:33`
- `src/armctrl/identification/runner.py:38`

当前工程约定是：

- 三类辨识轨迹默认都以 `q0=0` 为起点；
- 执行前默认调用 `reset_home()`；
- 这样做是为了安全，不是为了辨识最优。

#### 推论

这套逻辑非常适合 bringup 和复现，但它会把“安全 home 位姿”与“最佳辨识中心位姿”绑定在一起。  
这两个姿态在工程上通常不是同一个。

### 3.3 当前优化器还不是模型感知优化

#### 证据

- `src/armctrl/identification/optimization.py:1`
- `src/armctrl/identification/optimization.py:39`
- `src/armctrl/identification/optimization.py:111`
- `src/armctrl/identification/README.md:45`

`--optimize` 当前优化的是代理特征矩阵：

- `q`
- `dq`
- `ddq`
- `sin(q)`
- `cos(q)`
- `dq²`
- `q*dq`
- `q*ddq`

并不是论文里真正用于刚体动力学辨识的回归矩阵 `Y(q, dq, ddq)`。

#### 推论

当前 `--optimize` 的意义是：

- 避免明显糟糕、状态覆盖过窄的候选；
- 给出一个“相对丰富”的通用激励；

但它**不能证明**：

- ARX5 的基参数最可辨识；
- D435i 载荷项被最充分激励；
- 命令轨迹在实机执行后仍然保持最优。

### 3.4 当前软件安全限幅并不紧

#### 证据

- `src/armctrl/identification/safety.py:30`

当前保守软件限幅是：

- 关节位置：`[-1.5, 1.5] rad`
- 关节速度：`0.8 rad/s`
- 关节加速度：`5.0 rad/s²`

我用当前代码生成了一组候选参数，发现下面这些都能通过软件层预检查：

| Duration | Harmonics | Amplitude | 生成轨迹峰值速度 | 生成轨迹峰值加速度 |
|---|---:|---:|---:|---:|
| 16 s | 5 | 0.22 rad | 0.195 rad/s | 0.325 rad/s² |
| 20 s | 5 | 0.24 rad | 0.170 rad/s | 0.227 rad/s² |
| 16 s | 7 | 0.24 rad | 0.295 rad/s | 0.630 rad/s² |

#### 推论

从**当前软件限幅**看，默认 `12 s / 5 harmonic / 0.12 rad` 远不是被安全检查“逼出来”的上限。  
当前轨迹偏弱，主要是**默认值保守**，不是软件层限幅太紧。

### 3.5 当前模型里 D435i 的动力学作用方式

#### 证据

- `configs/models/README.md:7`
- `configs/models/README.md:10`
- `configs/models/README.md:25`
- `configs/models/X5_camera.urdf:227`
- `configs/models/X5_camera.urdf:228`

当前项目不是把相机挂在一个纯运动学的 `eef_link` 上，而是已经把 D435i 的等效载荷合并进 `link6`：

- 合并后质量：`0.653 kg`
- 合并后质心：`[0.06434756, 0, 0.00441041] m`
- SDK 逆动力学读 `link6`，不读 `eef_link` 的 inertial

#### 推论

对“带 D435i 整机”的动力学辨识来说：

- D435i 主要是一个**远端附加载荷**；
- 它最显著地改变的是肩肘腕俯仰方向的重力矩与耦合项；
- 对识别 payload 影响，`joint2` / `joint3` / `joint4` 比 `joint5` / `joint6` 更关键。

### 3.6 当前 URDF 对 `joint2` / `joint3` 非对称

#### 证据

- `configs/models/X5_camera.urdf:98`：`joint2` 限位是 `[0, 3.14]`
- `configs/models/X5_camera.urdf:132`：`joint3` 限位是 `[0, 3.14]`
- `configs/models/X5_camera.urdf:166`：`joint4` 限位是 `[-π/2, π/2]`
- `configs/models/X5_camera.urdf:205`：`joint5` 限位是 `[-1.67, 1.67]`
- `configs/models/X5_camera.urdf:258`：`joint6` 限位是 `[-1.57, 1.57]`

#### 推论

如果当前 home / zero 姿态落在 `joint2` / `joint3` 的下边界附近，那么**围绕绝对零做对称 Fourier** 对这两个关节天然不友好。  
它会让一半激励落在“不可达、被夹紧、或跟踪很差”的一侧。

### 3.7 当前真实运行数据已经显示 `joint2` / `joint3` 激励不足

运行目录：`runs/ident-sdk-fourier-20260428-221349`

#### 证据

从 `planned_trajectory.csv` 和 `raw_samples.csv` 统计：

| Joint | 命令跨度 | 实测跨度 | 命令最大速度 | RMS 跟踪误差 |
|---|---:|---:|---:|---:|
| J1 | 9.80° | 9.14° | 8.11°/s | 0.86° |
| J2 | 9.65° | 2.89° | 7.33°/s | 2.70° |
| J3 | 9.64° | 4.31° | 6.95°/s | 1.92° |
| J4 | 7.74° | 6.75° | 4.09°/s | 0.60° |
| J5 | 5.42° | 5.09° | 4.31°/s | 0.43° |
| J6 | 6.67° | 6.08° | 7.76°/s | 0.75° |

进一步看位置分布：

- 规划的 `J2` 最小值是 `-0.12 rad`，实测最小值只有 `-0.0044 rad`
- 规划的 `J3` 负半周占 `54.1%` 采样点，但实测 `J3` 全程几乎没有负角度

#### 推论

对当前这条运行，最有力的解释不是“采样率太低”，也不是“软件安全限幅太严”，而是：

1. `joint2` / `joint3` 围绕 `0` 的负半周在实机上没有真正执行出来；
2. 导致肩肘相关惯性/重力信息被显著削弱；
3. 所以这条数据集更像“轻微姿态扰动数据”，不够像“payload-rich 动力学辨识数据”。

## 4. 对当前现象的排序分析

### 问题

为什么当前 Fourier multisine 轨迹没有让机械臂“明显抬起来”，而只是围绕回中位置小范围活动？

### Ranked synthesis

| Rank | 解释 | 置信度 | 依据 |
|---|---|---|---|
| 1 | **激励中心姿态不对，`joint2/J3` 落在不利区间** | 高 | URDF 中 `joint2/3` 为 `[0, π]`，实际运行中这两轴负半周几乎没执行出来 |
| 2 | **默认幅值本来就小，目标就是保守安全** | 高 | CLI 默认幅值几乎固定为 `0.12 rad`，实测命令跨度只有约 `10°` |
| 3 | **当前优化器并不针对真实 regressor 最优** | 中 | `--optimize` 只优化代理特征矩阵，不会自动把轨迹推向 payload 最敏感构型 |
| 4 | **采样率是主要瓶颈** | 低 | 最高谐波频率只有 `5/12 ≈ 0.42 Hz`，`100 Hz` 采样远高于所需 |

## 5. 针对 `ARX5 2023 + D435i` 的 Fourier 参数设计建议

这里把“论文共识”和“当前项目约束”合在一起给出建议。

### 5.1 先明确辨识对象

#### 情况 A：你要识别“带 D435i 的当前整机”

建议：

- 保持相机、支架、线缆安装状态固定；
- 以 `X5_camera.urdf` 为目标模型；
- 让 `joint2` / `joint3` / `joint4` 产生足够大的重力杠杆变化；
- 不要指望只晃 wrist 就把 payload 参数估出来。

#### 情况 B：你要识别“裸臂参数”，相机只是临时装着

建议：

- 要么拆掉 D435i 后采数据；
- 要么至少做 `without payload / with payload` 两组数据，对比分离 payload 贡献；

这和综述里“with and without payload”的辨识流程是一致的。

### 5.2 对本项目最重要的设计变量：中心姿态 `q_c`

#### 建议

对当前 ARX5，不要把主 Fourier 轨迹继续中心在绝对零位。  
更合理的是把中心姿态挪到一个“肩肘都已经抬起来、又离限位有余量”的中间区间。

一个**起步级建议区间**：

- `joint1`: `0 ± 0.15 rad`
- `joint2`: 中心放在 `0.5 ~ 0.8 rad`
- `joint3`: 中心放在 `0.7 ~ 1.0 rad`
- `joint4`: 中心放在 `0.0 ~ 0.3 rad`
- `joint5`: 中心接近 `0`
- `joint6`: 中心接近 `0`

#### 说明

这不是论文直接给出的“ARX5 专用最优值”，而是基于以下事实的**工程推论**：

- `joint2/3` 在当前模型里不是对称限位；
- D435i 是远端载荷，肩肘抬起后重力矩变化更明显；
- 当前实测已经说明围绕零位时 `joint2/3` 的负半周执行不出来。

### 5.3 如果代码层面支持中心姿态，建议的 Fourier 参数

当前项目的 Fourier 生成器是**全关节共用一个 `amplitude_rad`**。  
如果后续实现了“每关节单独幅值”或“显式 `q0/q_center`”，推荐按下面两级走。

#### 建议方案 1：首轮可执行性验证

- `duration`: `16 s`
- `harmonics`: `3`
- `sample_hz`: `100`
- 中心姿态：按上节 `q_c`
- 每关节幅值：
  - `J1`: `0.12 ~ 0.15 rad`
  - `J2`: `0.18 ~ 0.22 rad`
  - `J3`: `0.18 ~ 0.22 rad`
  - `J4`: `0.12 ~ 0.18 rad`
  - `J5/J6`: `0.08 ~ 0.12 rad`

目的：

- 先验证 `joint2/3` 是否已经能在抬臂区间稳定跟踪完整正负半周；
- 先把“中心姿态错误”这个根因排掉。

#### 建议方案 2：主辨识轨迹

- `duration`: `16 ~ 20 s`
- `harmonics`: `5`
- `sample_hz`: `100`
- 中心姿态：按上节 `q_c`
- 每关节幅值：
  - `J1`: `0.12 ~ 0.18 rad`
  - `J2`: `0.22 ~ 0.30 rad`
  - `J3`: `0.22 ~ 0.30 rad`
  - `J4`: `0.15 ~ 0.22 rad`
  - `J5/J6`: `0.08 ~ 0.15 rad`

目的：

- 让 `joint2/3/4` 充分承担 payload 相关重力变化；
- 同时保留 wrist 的耦合信息，但不让 wrist 主导幅值预算。

#### 建议方案 3：只有在跟踪已经很好时才尝试

- `duration`: `18 ~ 24 s`
- `harmonics`: `5 ~ 7`
- 其余同上

前提：

- `joint2/3` 的实测跨度至少达到命令跨度的 `80%` 左右；
- RMS 位置误差已明显低于当前水平；
- 已确认没有碰撞、线缆拉扯、驱动器限流和明显振动。

### 5.4 在“当前代码不改”的前提下，能怎么选参数

这是更现实的一节，因为当前 CLI：

- 没有显式 `q0/q_center` 参数；
- 只有一个全局 `--amplitude`；
- 执行前默认回 home；
- `--optimize` 不是 regressor-aware。

因此，如果**不改代码**，你现在最多只能做“次优补救”。

#### 推荐区间

优先级从高到低：

1. **先降低谐波复杂度，换取更可靠执行**
   - `--duration 16`
   - `--harmonics 3`
   - `--amplitude 0.18`

2. **若跟踪稳定，再增加到主辨识级别**
   - `--duration 16` 或 `20`
   - `--harmonics 5`
   - `--amplitude 0.18 ~ 0.24`

3. **在没有解决中心姿态之前，不建议先上 `7` 次谐波**

#### 原因

因为当前最主要的问题不是轨迹“频谱不够复杂”，而是：

- 对关键关节来说，激励实际没有落在有效工作区；
- 实测轨迹和规划轨迹不一致；
- 这会直接破坏辨识矩阵的有效激励。

### 5.5 针对当前项目的实际可执行结论

如果你现在要给这套 ARX5 + D435i 设计一条“更像样的 Fourier 主辨识轨迹”，我会按下面顺序决策：

1. **先把中心姿态移到抬臂区间**  
   否则 J2/J3 的问题不会根治。

2. **再把 `duration` 拉到 `16~20 s`**
   这是为了在不过分提高导数量级的前提下，允许更大幅值。

3. **把 `harmonics` 先控制在 `3~5`**
   当前还没有证据表明更高谐波对实机有净收益。

4. **让 J2/J3 的幅值大于 wrist**
   因为 payload 在 `link6`，主信息不在 wrist 自转，而在肩肘改变重力杠杆臂。

5. **真正的轨迹优化应改成 regressor-aware**
   应该对 `Y(q, dq, ddq)`、Fisher information、或参数协方差做目标，而不是只对代理特征矩阵做评分。

## 6. 对一般机械臂的通用设计建议

这部分脱离 ARX5，本质上回答“不同构型/型号，激励轨迹该怎么选”。

### 6.1 轨迹形式怎么选

#### 情况 1：先做重力 / payload

优先：

- 准静态单关节扫描；
- 两三个主关节组合改变末端高度；
- 低速、多停留点。

适用于：

- 先估总质量、质心；
- 验证 URDF payload 假设；
- 工具/相机安装后先做一次载荷校正。

我最终要识别“一直带 D435i 的当前整机”。文档中提到的工具/相机安装后先做一次载荷校正。中的载荷校正是什么意思，要在 sdk 中修改什么payload？


#### 情况 2：做摩擦

优先：

- 正反向；
- 多恒速段；
- 尽量减少其他关节同时大幅运动。

#### 情况 3：做完整刚体基参数

优先：

- 多关节耦合周期轨迹；
- Fourier / modified Fourier / 带边界处理的周期参数化；
- 直接优化 regressor 可辨识性指标。

### 6.2 构型不同，重点不同

#### 6R 关节型串联臂

- 重点看 shoulder / elbow 是否真正改变了重力杠杆臂；
- 若有末端 payload，优先提高肩肘激励质量；
- wrist 更多用于解耦，但不应抢走主要幅值预算。

#### SCARA / 平面机械臂

- 平面内惯性耦合常比空间 6R 简单；
- 若有竖直轴或升降轴，必须单独覆盖其重力/摩擦特性；
- 常可用更低谐波数完成足够激励。

#### 高减速比工业臂 / 协作臂

- 要更重视跟踪器带宽、齿隙、柔性和限流；
- 常常宁可用更长周期、更低最高谐波，也不要盲目“激进高频”。

#### 轻量柔性臂

- 必须显式避开结构模态；
- 仅凭刚体 regressor 优化出来的高阶轨迹，实机可能完全不可用；
- 这类系统更需要频带约束和安全几何约束。

### 6.3 具体参数怎么选

可以用下面这套顺序：

1. **先定中心姿态 `q_c`**
   - 离硬限位保留足够余量；
   - 能显著改变主惯性/重力项；
   - 避开奇异与明显自碰撞区。

2. **再定幅值 `A_j`**
   - 按关节作用不对称分配；
   - 主动力学关节幅值更大；
   - wrist / 次要关节幅值更小。

3. **再定 `T` 与 `H`**
   - 优先让轨迹可跟踪；
   - `H/T` 不要逼近驱动器或结构不擅长的频带；
   - 需要更大激励时，先增 `T` 或 `A_j`，再考虑增 `H`。

4. **最后做数值优化**
   - 目标应是 regressor/Fisher information；
   - 优化后还要用实测执行轨迹重新评估，而不是只看命令轨迹。

## 7. 本项目当前最值得记住的约束

### 7.1 这几条是直接证据

- 当前实机执行前默认回 home：`src/armctrl/identification/runner.py:63`
- 当前 CLI 没有显式中心姿态参数：`src/armctrl/cli/arx5ctl.py:160`
- 当前 Fourier 默认幅值很保守：`src/armctrl/cli/arx5ctl.py:438`
- 当前优化器不是基于真实 regressor：`src/armctrl/identification/optimization.py:111`
- 当前软件安全限幅不是真正的主瓶颈：`src/armctrl/identification/safety.py:30`
- D435i 已经并入 `link6`，因此主辨识信息主要通过肩肘腕俯仰显现：`configs/models/README.md:10`

### 7.2 这几条是基于证据的推论

- 围绕绝对零生成 Fourier 对当前 ARX5 并不合适，至少对 `joint2/3` 不合适。
- 当前 run 的“只抬起来一点点”不是偶然，而是当前设计逻辑的自然结果。
- 若不改变中心姿态，仅靠 `--optimize` 或增加谐波数，收益会很有限。

## 8. 尚未解决的未知量

以下问题，当前仓库和这次运行数据还不能完全回答：

1. **SDK 真正的 home pose 数值是多少**  
   这决定推荐中心姿态与 home 的距离有多大。

2. **驱动器的实际限流 / 限矩 / 软限位策略**  
   当前数据强烈暗示 `joint2/3` 的负半周存在执行约束，但还不能单凭仓库代码证明是哪个环节造成的。

3. **D435i 支架、螺丝、线缆的真实等效质量与质心**  
   当前模型只是一版起步近似。

4. **相机/线缆是否引入额外碰撞或拖拽约束**

因此，本文给出的 ARX5 参数建议应视为：

- **对当前仓库与当前 run 的最佳工程推论**，
- 不是“已经过系统实机扫参验证的唯一最优值”。

## 10. 最后一句话

对当前项目，真正该优先解决的是：

**让 `joint2` / `joint3` 在“抬臂后的中间姿态”里被充分、可跟踪地激励。**

在这个前提满足之前，单纯围绕绝对零位做保守 Fourier，即使表面上“用了优化”，也很难产出高质量的 payload-rich 动力学辨识数据。
